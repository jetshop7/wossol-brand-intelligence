## Material finding — evidence-grade inconsistency

The document defines:

- **EVIDENCED (public artifact/contract)** as a first-party artifact that directly shows a field/workflow/interface/contract;
- **CLAIMED / DEPTH UNVERIFIED** as provider-stated capability without sufficient inspectable implementation depth.

But the seven-lens matrix applies `PARTLY EVIDENCED` inconsistently in at least two places.

### Delivered

Current matrix language:
> `PARTLY EVIDENCED` published order-level remittance fields: collected, deducted, paid.

The public FAQ **states** that every remittance comes with an order-level statement containing collected / deducted / paid. The Director did not find an inspectable statement artifact/API schema/authenticated UI proving those fields beyond the provider's statement.

Required correction:
- downgrade this item to **CLAIMED / DEPTH UNVERIFIED**;
- retain the exact public claim and caveat;
- do not weaken the broader strategic conclusion that Delivered publicly claims order-level reconciliation.

### Fufills

Current matrix language:
> `PARTLY EVIDENCED` public interface artifacts show queues/settlement/country health.

The public site includes dashboard imagery/interface-like artifacts and detailed operational claims. These are useful public artifacts but are provider-controlled marketing surfaces, not authenticated product inspection.

Required correction:
- either:
  - keep `PARTLY EVIDENCED` but explicitly label the evidence as **provider-controlled public interface imagery / marketing artifact only**, not verified product behavior; or
  - downgrade to **CLAIMED / DEPTH UNVERIFIED** if the artifact cannot support the specific fields asserted.
- use one evidence rule consistently across Ximpli, Fufills, MDM and CODPARTNER screenshots/mockups.

## Minor consistency correction

Where the document uses `EVIDENCED`, `PARTLY EVIDENCED`, and `CLAIMED`, make the legend explicit about whether **provider-controlled public UI imagery/mockups** qualify for `PARTLY EVIDENCED`.

The classification should answer:

> What is evidenced — the existence of a public artifact, or the actual product capability?

Recommended rule:
- public screenshot/UI artifact can evidence **what the provider publicly presents in the interface artifact**;
- it does **not** evidence live availability, correct calculation, merchant rights, persistence, or production behavior;
- marketing text alone remains `CLAIMED / DEPTH UNVERIFIED`;
- API/documented field contracts can be `EVIDENCED (public contract)` for the contract itself.
